一、字段变更

  • 彩金领取方式与是否需要人工审核是两个独立维度，请勿混淆：①晋级礼金、日福利礼金、周福利礼金、月福利礼金的领取动作统一固定为会员手动领取（不提供"自动生成即到账"式的免点击发放，此项与上一轮一致，未再调整）；②「发放方式」（自动发放／人工发放，逐等级配置，非逐礼金类型单独配置）决定会员点击"领取"后彩金是系统自动审核通过直接到账，还是进入待审核状态、需运营在「VIP福利彩金审核」页人工审核通过后才发放，新增/编辑抽屉与主列表均沿用该字段。
  • 新增：日福利礼金NEW、日流水NEW（日福利礼金的达标门槛，逻辑与"周流水→周福利礼金"一致）
  • 新增：月福利礼金NEW、月流水NEW（逻辑同上）；月福利礼金固定每月16日结算生成上一自然月的奖励
  • 日/月福利礼金不再提供逐等级"是否启用"勾选：某等级若不需要该项福利，直接将对应金额配置为 0 即可；是否面向全体等级"整体开放"该福利，统一由「客户端展示设置」中的展示字段勾选控制（勾选状态同时决定是否实际生成待领取记录，见第五节）

二、晋级礼金 / 日福利礼金 / 周福利礼金 / 月福利礼金：统一手动领取

  • 达标后礼金进入"待领取"状态，由会员在客户端「我的特权」页主动点击领取；领取前不入账，也不计入提现流水，领取后按该等级配置的「发放礼金稽核倍数」（客户端展示别名"提现流水倍数"）计入提现流水门槛——若该等级发放方式为人工发放，则需运营审核通过后才计入；若为自动发放，会员点击"领取"后系统即自动审核通过并计入
  • 日 / 周 / 月福利礼金能否"生成"，分别取决于对应周期内是否满足日流水 / 周流水 / 月流水门槛；跨级晋级礼金仍按每一级依次生成独立的"待领取"记录，不合并

三、发放方式：自动发放 / 人工发放，决定是否需要人工审核

  • 入口：新增/编辑抽屉底部的「发放方式」单选（自动发放／人工发放），逐等级配置；主列表同步展示「发放方式」列，运营无需进入抽屉即可确认口径
  • 自动发放：会员在客户端点击"领取"后，系统直接判定审核通过，彩金立即到账，「VIP福利彩金审核」页记录审核方式＝"自动"、审核人＝"系统"
  • 人工发放：会员在客户端点击"领取"后，进入待审核状态（客户端按钮展示为"审核中"，彩金尚未到账），需运营在「VIP福利彩金审核」页人工审核通过后，才正式发放到账，审核方式＝"手动"、审核人＝实际操作的运营账号
  • 与「领取规则设置」的关系：两者是互不影响的独立维度——「发放方式」决定"会员点击领取之后，钱多久/怎么到账"；「领取规则设置」（见第四节）决定"会员迟迟不点领取，奖励本身要不要过期作废"。一笔奖励从生成到会员实际点击领取之前，均按「领取规则设置」的方案处理；会员点击领取的那一刻起，才切换到「发放方式」决定的审核流程

四、领取规则NEW：二期仅保留「未领取作废」

  • 二期生效范围：本期「领取规则设置」仅保留未领取作废，作为全局统一规则；适用于日福利礼金、周福利礼金、月福利礼金。晋级礼金不受跨期作废限制，达标生成后永久保留至会员领取。
  • 未领取作废：跨天、跨周、跨月时，对应周期福利仍未领取的，由系统自动回收作废；数据库保留作废记录供查询核对，客户端不再展示该笔可领取奖励。
  • 所有统计、结算、判定时间均按北京时间（UTC+8）执行；日福利次日00:00~02:00结算上一自然日；周福利每周一00:00~02:00结算上一自然周；月福利每月16日00:00~02:00结算上一自然月。
  • 三期预留（本期不开发）：以下三项仅保留需求痕迹，统一以删除线标识，不进入二期开发/测试范围：
    迭代规则说明
    三期未领取转发跨周期奖励继续保留并发送站内信/邮件提醒。三期，本期不开发
    三期受众控制领取通过充值受众条件控制已生成奖励是否可领取。三期，本期不开发
    三期受众控制发奖通过充值受众条件控制奖励是否生成。三期，本期不开发
  • 二期状态闭环：周期奖励生成 → 待领取 → 会员领取 → 按等级发放方式进入自动审核通过或人工待审核；若跨周期仍未领取 → 系统自动回收作废。晋级礼金不进入跨期作废分支。

五、日/周/月流水门槛与客户端展示设置调整

  • 新增展示字段：日流水NEW、月流水NEW、日福利礼金NEW、月福利礼金NEW
  • 「晋级礼金」「周福利礼金」「日福利礼金」「月福利礼金」四项不只是控制客户端展示：取消勾选后，即使对应VIP等级已经配置了具体金额，系统也不会再实际生成待领取记录（即不派发该项礼金）；其余字段（VIP等级名称、门槛、日流水、周流水、月流水、30天保级经验、衰退基础值、提现流水倍数）取消勾选仅影响客户端是否显示，不影响后台判定和实际发放
  • 「客户端展示设置」中的规则文案字段「周流水规则」更名为「流水福利规则」：因日/周/月流水的达标判定逻辑一致（达标发放、未达标不发放），不再单独按周期区分文案字段，统一在同一段文案中说明日/周/月三档的结算周期与判定逻辑，多等级流水规则、未达标流水结转两条例外规则保留并注明"仅周流水适用"；字段仍维持三段结构（晋升规则/保级规则/流水福利规则），不新增字段，不影响其余两段文案

六、晋级礼金不受「领取规则设置」任何方案约束、永不过期NEW

  • 「领取规则设置」方案三·受众控制领取、方案四·受众控制发奖中的"受众条件"特指充值条件，其作用范围仅为日/周/月福利礼金，用于控制这三类礼金"是否可领取"（方案三）或"是否生成"（方案四）；方案一/二"跨期未领取转发/作废"同样仅作用于日/周/月福利礼金
  • 晋级礼金不受方案一/二/三/四任何一项约束：只要会员达到晋级门槛，晋级礼金即正常生成为"待领取"状态，不需要在配置天数内完成充值即可领取，不存在"已生成但需先充值"或"因未充值本期不生成"的情形
  • 晋级礼金不会过期作废：达标生成后，无论间隔多久、跨多少个自然日仍未领取，都不会被系统按方案一/二回收作废，始终保持可领取，会员可随时回到VIP福利页面完成领取（历史等级中长期未领取的晋级礼金同理，可通过页面顶部"一键领取"一并领取）

七、保级衰退与恢复机制，替换原90天保级机制NEW

  • 90天保级流水字段更名为「30天保级经验」：保级考核周期由90天调整为30天，字段口径由"流水金额"统一改为与晋级门槛一致的"VIP经验"（即原「待换算预期抽佣金额余量(pool)」，数值沿用同一份数据不变，仅命名与口径调整）；周期内累计经验达标则保级成功，重新开始下一轮30天周期
  • 新增「衰退基础值」字段（逐等级配置，单位：经验/天）：30天内未达标且周期内VIP经验完全没有任何增长的，从第31天起按该值开始扣除VIP经验，正式进入衰退；周期内哪怕有部分增长（即使未达标），也不触发衰退，顺延至下一个30天周期继续观察
  • 衰退加速：进入衰退后每连续15天仍无经验增长，衰退速度提升一档，直至重新产生经验为止：
    阶段连续未活跃时间衰退倍率说明
    正常保级期第1-30天0未触发衰退
    衰退阶段1第31-45天1×按该等级「衰退基础值」每日扣除VIP经验
    衰退阶段2第46-60天2×连续15天仍无经验增长后加速
    衰退阶段3第61-75天3×再次连续15天仍无经验增长
    衰退阶段4第76天起4×继续不活跃则维持最高倍率衰退，不再继续加速
  • 恢复机制：会员一旦重新产生VIP经验，立即停止衰退，进入2倍经验恢复期，期间新获得经验按2倍计入，直至恢复到衰退/初始化调整前锁定的原VIP等级及原经验值，之后恢复正常1倍增速
  • 恢复期再次不活跃（边界规则，本轮明确）：尚未恢复至锁定目标便再次停止产生经验时，不立即衰退、不沿用上一轮衰退倍率，重新进入30天保级观察；只有完整30天未达保级要求且0经验增长，才从第31天重新按1×衰退。原恢复目标持续保留，后续再次活跃时重新按2倍经验继续恢复至原目标
  • 与降级的关系（本轮明确）：新机制不再有"周期未达标即刻掉1级"的硬性跳变；VIP经验因持续衰退跌破当前等级自身门槛时，于次日定时评估中按经验值实时对照等级门槛表自然回落至对应低等级，与晋级判定复用同一套按「VIP经验」字段判断的等级评估逻辑（降级任务每天执行一次，方向相反）；经验回升超过当前所处等级晋升阈值后可重新恢复原等级
  • 降级后衰退基础值如何取值（本轮明确）：衰退速度（1×/2×/3×/4×）绑定"连续不活跃天数"，不受降级影响，按自身节奏继续跳档；衰退基础值则按会员当前所处等级动态取值，降级后次日起改用新（低）等级配置的衰退基础值计算每日扣除量，不沿用降级前那个等级的衰退基础值，不额外引入"衰退起始等级"状态
  • 衰退与降级仅影响VIP经验与等级判定本身，不影响已生成但尚未领取的日/周/月/晋级礼金记录，详见「需求背景」页第四节

整理自本轮迭代（管理后台礼金机制调整 + 客户端交互升级）需求沟通，供产品、运营、研发对齐口径使用

一、背景与目标

VIP-按抽佣体系用于承接按抽佣系数折算的会员等级成长与权益发放。此前版本仅支持"晋级礼金"与"周福利礼金"两类奖励，会员活跃度激励颗粒度较粗，且发放方式（自动/人工/手动）在不同礼金类型间不统一，运营难以在列表页直接判断当前发放口径。本轮迭代的目标：①补齐"日、月"两个更高频/更长周期的流水福利礼金，让激励覆盖日/周/月/晋级四个颗粒度，形成完整的活跃度体系；②将四类礼金的领取动作统一为"会员手动领取"，并与「发放方式」（自动发放/人工发放，逐等级配置）明确关联——决定会员领取后是否需要运营人工审核，通过UI标识让运营无需进入配置弹窗即可确认领取口径与发放口径；③新增「领取规则设置」，二期仅保留未领取作废，明确会员逾期未领取奖励时系统自动回收，补齐业务闭环；未领取转发 / 受众控制领取 / 受众控制发奖三期；同时明确未领取作废不适用于晋级礼金——晋级礼金达标即可无限期领取，不会因跨期未领取或未充值等条件被限制、作废或过期；④同步升级客户端「我的特权」页交互，引入"去投注 / 领取"双态按钮、当前等级卡片置顶展示、页面顶部全局"一键领取"跨等级找回遗漏奖励入口，提升会员端可用性；⑤原"90天保级流水，未达标直接降1级"的保级机制判定过于生硬、缺乏活跃度衰减的缓冲空间，本轮引入「保级衰退与恢复机制」替换之——保级考核周期缩短为30天，未达标且周期内0经验增长的才进入VIP经验衰退，衰退速度随连续不活跃天数分档加速，重新活跃后立即停止衰退并获得2倍经验恢复加成，等级本身不再因单次周期未达标而硬性跳变式下降，详见第四节。

四、核心规则设计

4.1 手动领取机制（领取动作统一，不代表发放方式统一）

晋级礼金、日福利礼金、周福利礼金、月福利礼金四类奖励，领取动作统一固定为"达标后由会员在客户端主动领取"，不提供"免点击自动到账"式的可配置项。领取前不入账、不计入提现流水。需要特别说明：会员点击"领取"这个动作与点击之后是否需要人工审核才能到账是两个独立维度——前者（本节）在四类礼金间保持统一，均由会员手动点击；后者由 3.2 节的「发放方式」逐等级决定。

4.2 发放方式：自动发放 / 人工发放（决定是否需要人工审核）

「VIP列表-按抽佣」新增/编辑抽屉底部的「发放方式」字段，逐VIP等级配置，二选一：

  • 自动发放：会员点击"领取"后，系统直接判定审核通过，彩金立即到账；「VIP福利彩金审核」页对应记录审核方式为"自动"、审核人为"系统"
  • 人工发放：会员点击"领取"后，进入待审核状态（彩金尚未到账，客户端按钮展示为"审核中"），需运营在「VIP福利彩金审核」页人工审核通过后，才按该等级配置的"发放礼金稽核倍数"（客户端展示别名"提现流水倍数"）计入提现流水门槛并正式发放；若审核拒绝，该笔奖励作废

「发放方式」与 3.4 节的「领取规则设置」是两个互不影响的独立维度：领取规则决定"奖励生成后，会员迟迟不点领取，要不要过期作废"；发放方式决定"会员点击领取之后，要不要人工审核才能到账"。一笔奖励从生成到会员实际点击领取之前，按领取规则处理；会员点击领取的那一刻起，才切换到发放方式决定的审核流程。

4.3 日 / 周 / 月流水福利礼金

新增"日流水→日福利礼金""月流水→月福利礼金"两组字段，与既有"周流水→周福利礼金"逻辑一致：会员在对应统计周期内的有效投注流水达到门槛，即生成该等级对应的待领取奖励。某等级若不需要开放某项福利，将金额配置为 0 即可；是否面向全体等级整体开放该福利，由「客户端展示设置」中对应展示字段的勾选统一控制（该勾选同时决定是否实际生成待领取记录）。月福利礼金固定于每月16日结算生成上一自然月的奖励。

其中周福利礼金额外遵循两条判定规则（本轮明确，日/月福利礼金同一账号在同一周期内仅对应单一等级门槛，不涉及多级重叠判定）：①多等级流水规则——同一统计周期内若会员的有效投注流水同时满足多个VIP等级的周流水门槛，不逐级叠加发放，仅按会员当前所处的VIP等级发放对应最高等级的周福利礼金；②未达标流水结转——若当前统计周期内未满足当前VIP等级（含本周内晋升后的新等级）的周流水门槛，本周期不发放任何周福利礼金，且未达标部分的有效投注流水自动结转至下一统计周期继续累计，不清零。

4.4 领取规则：跨期未领取奖励处理（二期范围收口）

五、与晋级 / 保级衰退与恢复机制的关系（闭环说明）

9月23日更新 升级及恢复任务调整为每20分钟执行一次；降级任务调整为每天执行一次；升降级统一以会员「VIP经验」字段为判断标准。

会员有效投注最终折算为"VIP经验"（即后台字段与「待换算预期抽佣金额余量(pool)」同一概念，本节统一按"VIP经验"表述），与各等级"晋升所需经验值门槛"处于同一把绝对刻度上；具体折算口径由抽佣系数等后台参数决定，属既有实现范畴，本节不再展开。保级衰退与恢复机制（详见5.1~5.5节）直接作用于这个已折算完成的"VIP经验"绝对值本身，与投注如何折算为经验是两套相互独立的机制，衰退扣减、降级后重新定位等级，均不需要反向拆解回投注金额重新折算。晋级与恢复任务调整为每20分钟执行一次：系统按会员当前「VIP经验」字段实时对照等级门槛，达到下一等级的"晋升所需经验值门槛"即触发晋级；恢复期同样按当前「VIP经验」字段进行恢复判断。系统生成一次性晋级礼金待领取记录，并开启该等级的30天保级周期；同一账号若经验增长足以连续跨越多个等级，各等级晋级礼金依次发放。

5.1 30天保级周期与衰退触发（本轮替换原90天保级机制）

会员达到当前VIP等级后，以30天为一个保级考核周期（每等级独立配置"30天保级经验"门槛）：周期内累计VIP经验达到该等级的保级经验要求，本周期保级成功，等级和已获得的VIP经验正常保留，并重新开始下一轮30天周期；若30天内未达到保级经验要求，且整个周期内没有任何VIP经验增长，则从第31天起按该等级的"衰退基础值"开始扣除VIP经验，正式进入衰退。

30天内虽未达到保级经验要求，但周期内有任意VIP经验增长（哪怕未达标）的，本轮明确：不视为触发衰退的"0增长"条件，本周期结束后直接顺延开启下一个30天周期继续观察，不清零已有VIP经验，仅当连续出现"整个30天周期内0增长"时才会进入衰退——与「产品规则摘要」"30天未保级且0经验增长"的双重条件表述保持一致。

5.2 连续不活跃加速衰退

进入衰退后，若会员仍然没有任何VIP经验增长，则每连续15天提升一次衰退速度，直至重新产生经验为止：

阶段连续未活跃时间衰退倍率说明
正常保级期第1-30天0未触发衰退
衰退阶段1第31-45天1×按该等级"衰退基础值"每日扣除VIP经验
衰退阶段2第46-60天2×连续15天仍无经验增长后加速
衰退阶段3第61-75天3×再次连续15天仍无经验增长
衰退阶段4第76天起4×继续不活跃则维持最高倍率衰退，不再继续加速

5.3 恢复机制

会员一旦重新产生VIP经验（不论金额大小），立即停止衰退，并进入2倍经验恢复期：期间新获得的VIP经验按2倍计入，直至恢复到衰退/初始化降级发生前锁定的原VIP等级及原VIP经验值目标为止；仅恢复到原等级最低门槛时不提前结束2倍加成，达到锁定原经验值后2倍加成结束，恢复正常1倍经验增长。

恢复期再次不活跃（边界规则，本轮明确）：会员进入2倍经验恢复期后，如尚未恢复至锁定目标便再次停止产生VIP经验，不立即恢复衰退，也不沿用上一次1×/2×/3×/4×衰退倍率；从再次停止产生经验之日起，重新进入一轮30天保级观察周期。若该30天内达到当前等级「30天保级经验」要求，则保级成功并开启下一周期；若未达标但周期内曾产生VIP经验，则本周期不触发衰退，顺延下一轮30天继续观察；仅当某一完整30天周期未达到保级要求且周期内0经验增长时，才从该轮第31天重新进入衰退阶段1（1×），后续再按连续不活跃天数每15天提升至2×、3×、4×。期间原「恢复目标等级 + 恢复目标经验值」持续保留、不重置；会员之后再次产生VIP经验时，停止新的衰退并重新按2倍经验继续向原锁定目标恢复，直至完全恢复后才清除恢复目标。

5.4 衰退与降级的关系（本轮明确，替代原90天机制的"未达标直接降1级"）

新机制下不再有"周期未达标即刻掉1级"的硬性跳变：VIP经验的衰退是持续、平滑的过程，等级本身不会仅因进入衰退而立即下降。当VIP经验因持续衰退而跌破当前等级自身的晋升门槛时，将于每日降级任务执行时按VIP经验实时对照各等级门槛表，自然回落至对应的低等级——与晋级判定复用同一套以「VIP经验」字段为判断标准的等级评估逻辑，仅方向相反（晋级看"够不够上一级"，衰退降级看"是否已跌破当前级"）。降级后VIP经验回升，超过当前所处等级的晋升阈值时，可重新恢复至原VIP等级。

本轮明确：衰退过程中若发生上述自然降级，衰退速度（1×/2×/3×/4×）与衰退基础值分属两个独立变量——衰退速度绑定"连续不活跃天数"，不受降级影响，按自身节奏继续跳档；衰退基础值则按会员"当前所处等级"动态取值，降级后次日起改用新（低）等级配置的衰退基础值 × 当前衰退速度计算每日扣除量，不沿用降级前那个等级的衰退基础值——与晋级判定"pool值实时对照等级门槛表"复用同一套每日评估引擎、同一个"当前等级"定义，不额外引入"衰退起始等级"的独立状态。由于衰退基础值一般随等级降低而减小，降级后每日扣除的经验绝对值会自动变小，衰退不会出现越掉级越猛的连锁效应。
本轮明确：单日衰退扣减不做"跨等级门槛拆分"——不会因为当日应扣金额（衰退基础值×衰退速度）超出到当前等级门槛的缓冲区间，就只扣到刚好卡在门槛线上、剩余部分顺延到次日再扣；系统按当日应扣金额整笔全额扣除，扣减后再重新对照等级门槛表定位所在等级——若扣减幅度较大，允许单日内连续下降多个等级，与晋级判定"同一账号单日经验增长足以连续跨越多个等级、各级晋级礼金依次发放"对称一致。示例：会员当前VIP3（门槛300），VIP经验315，当日衰退基础值45、速度1×：整笔扣除45，315－45＝270；270已跌破VIP3门槛300，但仍≥VIP2门槛200，故直接降级至VIP2；次日起改用VIP2自身的衰退基础值计算扣除量（与上一条"降级后衰退基础值如何取值"衔接）。

5.5 与四类礼金的关系

VIP经验衰退、降级仅影响VIP经验值与等级判定本身，不影响已生成但尚未领取的日/周/月/晋级礼金记录——这些记录仍按自身周期边界与「领取规则设置」独立处理，不随等级升降或经验衰退而联动清零或恢复（与「领取规则设置」四个方案的关系见4.5节：晋级礼金不受任何方案约束、达标即可无限期领取，不因等级衰退/降级而作废已生成的晋级礼金）。四类礼金、晋级/保级衰退与恢复机制、领取规则三者共同构成完整闭环：晋级/保级决定"能拿到哪个等级的权益"，日/周/月流水门槛决定"该周期是否生成奖励"，领取规则决定"生成后未及时领取如何处理"，保级衰退与恢复机制决定"经验/等级本身如何随活跃度变化"。
